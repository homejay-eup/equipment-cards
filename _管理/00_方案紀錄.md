## [2026-05-23] P01 | 技術選型回顧（遷移前存檔）

**討論背景**：從舊版 CLAUDE.md 結構遷移至 D 型架構，順便存檔原有技術選型決策。

**決策結果（已確認）**：
- 前端：Next.js 14 App Router + Tailwind CSS + shadcn/ui
- 資料庫：Supabase（PostgreSQL + Auth + RLS）
- 照片儲存：Cloudinary（25GB 免費）
- 部署：Vercel Hobby（push 即自動部署）
- 前端搜尋：Fuse.js（786 筆小資料，全客戶端）

**排除原因**：
- Cloudflare R2：只有 10GB 免費，且需信用卡
- Firebase：比 Supabase 複雜，PostgreSQL 更熟悉
- 伺服器端搜尋：資料量小，Fuse.js 即可，省 API 費用

**影響的步驟**：所有 Step 1–8（已完成）

## [2026-06-16] P01 | 設備文件查詢與維護方案（走 Google Drive）

**討論背景**：業務需快速查到設備相關文件（規格書/合約書等）。現有文件放在公司內網
`\\10.1.0.5\業務部\A++產品規格書`，但料卡網站部署在公開的 Vercel。需在「業務快速查」
與「維護者好維護」之間找到可行做法。

**關鍵限制**：
- 內網 UNC 路徑網頁連不到：瀏覽器擋 https 頁面裡的 `file://`（系統 `isSafeUrl()` 也只允許 http/https），
  且內網路徑只有在公司、連得到 10.1.0.5 的人能開。
- 786 筆無法手動逐筆貼網址，必須能批次/自動化。

**使用者確認的前提**：
- (a) 業務也會在外/手機查 → 必須走雲端
- (b) 公司有 Google Workspace 可用
- (c) 現有檔名很亂，需先 AI 對照整理，往後以「品號＋品名」規範命名

**考慮的選項**：
| 選項 | 說明 | 結論 |
|------|------|------|
| A. Google Drive 共用雲端硬碟 | 檔案搬上 Drive，命名規範＋腳本自動回填連結 | ✅ 採用 |
| B. 內網檔案閘道 | 把 10.1.0.5 用 http 對外，卡片連內網主機 | ❌ 排除 |
| C. 上傳進系統 | PDF 存 Supabase Storage / Cloudinary | ❌ 排除 |

**決策結果（已收斂，待執行）**：採 **A. Google Drive**，分三階段：
- Phase 0：AI 對照整理檔名（匯出 786 筆料卡清單 + 列現有檔名 → AI 產對照表 → 人工複核 →
  重新命名 `品號_品名_類型.副檔名` 搬上 Drive 共用硬碟，分享設為 eup.com.tw 網域內可檢視）
- Phase 1：一次性 Node 腳本用 Drive API 掃資料夾、取 fileId 組連結、批次寫回 `documents` 欄位
- Phase 2：固定命名規範＋同步機制（重跑腳本或 Apps Script 排程）；備援擴充 CSV 批次匯入 documents 欄位

**排除原因**：
- B 內網閘道：只有在公司能開，業務在外打不開；要養伺服器，與「好維護」矛盾
- C 上傳進系統：Supabase 免費僅 1GB 不夠 786 PDF；且要逐筆搬、脫離 Workspace 權限體系

**重要前提（網站端已現成）**：`documents` JSONB 欄位、CardDetailDialog 顯示、CardFormDialog
編輯均已完成，核心顯示元件不需修改。工作量集中在「搬檔上 Drive ＋ 批次灌連結」。

**待實作前再確認的小決策**：Phase 2 同步用手動重跑或 Apps Script 排程、一卡多文件如何帶類型、
Drive API 走 service account 或個人授權。

**影響的步驟**：Step 30（文件管理，待建立）

## [2026-08-12] equipment-cards | 群組/套餐管理架構優化（新 Step，規劃中，尚未執行）

**討論背景**：「我的關注」跟「設備套餐」兩個頁面功能已經很完整（清單/照片切換、數量、拖曳排序等），但使用者反映實務上群組/套餐的組合情境太多太亂（客戶、車款、大小車、車頭車尾、主機型號、鏡頭方案、周邊、既有設備、業務性質…），難以維護，考慮是否要另建頁面解決。

**考慮的選項**：
| 選項 | 說明 | 結論 |
|---|---|---|
| A. 加分類標籤方便篩選 | 套餐/群組加結構化標籤，不動資料模型本質 | ✅ 採用（輕量、符合「維護便利性」優先目標） |
| B. 模組化組合式套餐（底稿+差異疊加/積木組裝） | 主機/鏡頭/周邊各自成模組，套餐由模組拼裝而成 | ❌ 排除——使用者確認「選項會陸續變動＋不同客戶內容相似但不完全一樣」，模組化反而增加維護負擔跟操作複雜度，划不來 |
| C. 進貨清單另建獨立實體 | 進貨清單改用專門的新資料模型，跟安裝套餐脫鉤 | 暫緩，本輪聚焦標籤分類先解決「找範本」問題，未來有需要再議 |

2. 善用既有「複製套餐」功能：找最接近的範本複製一份再手動微調，取代「模組自動組裝」（更符合「內容相似但不完全一樣」的實務現實）
3. 補齊「設備套餐」頁面缺的**跨套餐批次替換**功能——「我的關注」的替換料卡彈窗已有「此料卡同時存在於」勾選多個群組一次套用的功能，「設備套餐」目前沒有這個，需要補齊；範圍明確，可直接排入執行
