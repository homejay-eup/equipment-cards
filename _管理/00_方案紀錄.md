## [2026-06-16] P01 | 設備文件查詢與維護方案（走 Google Drive）

**討論背景**：業務需快速查到設備相關文件（規格書/合約書等）。現有文件放在公司內網
`\\10.1.0.5\業務部\A++產品規格書`，但料卡網站部署在公開的 Vercel。需在「業務快速查」
與「維護者好維護」之間找到可行做法。

**關鍵限制**：
- 內網 UNC 路徑網頁連不到：瀏覽器擋 https 頁面裡的 `file://`（系統 `isSafeUrl()` 也只允許 http/https），
  且內網路徑只有在公司、連得到 10.1.0.5 的人能開。
- 786 筆無法手動逐筆貼網址，必須能批次/自動化。

**使用者確認的前提**：
- (a) 業務也會在外/手機查 → 必須走雲端
- (b) 公司有 Google Workspace 可用
- (c) 現有檔名很亂，需先 AI 對照整理，往後以「品號＋品名」規範命名

**考慮的選項**：
| 選項 | 說明 | 結論 |
|------|------|------|
| A. Google Drive 共用雲端硬碟 | 檔案搬上 Drive，命名規範＋腳本自動回填連結 | ✅ 採用 |
| B. 內網檔案閘道 | 把 10.1.0.5 用 http 對外，卡片連內網主機 | ❌ 排除 |
| C. 上傳進系統 | PDF 存 Supabase Storage / Cloudinary | ❌ 排除 |

**決策結果（已收斂，待執行）**：採 **A. Google Drive**，分三階段：
- Phase 0：AI 對照整理檔名（匯出 786 筆料卡清單 + 列現有檔名 → AI 產對照表 → 人工複核 →
  重新命名 `品號_品名_類型.副檔名` 搬上 Drive 共用硬碟，分享設為 eup.com.tw 網域內可檢視）
- Phase 1：一次性 Node 腳本用 Drive API 掃資料夾、取 fileId 組連結、批次寫回 `documents` 欄位
- Phase 2：固定命名規範＋同步機制（重跑腳本或 Apps Script 排程）；備援擴充 CSV 批次匯入 documents 欄位

**排除原因**：
- B 內網閘道：只有在公司能開，業務在外打不開；要養伺服器，與「好維護」矛盾
- C 上傳進系統：Supabase 免費僅 1GB 不夠 786 PDF；且要逐筆搬、脫離 Workspace 權限體系

**重要前提（網站端已現成）**：`documents` JSONB 欄位、CardDetailDialog 顯示、CardFormDialog
編輯均已完成，核心顯示元件不需修改。工作量集中在「搬檔上 Drive ＋ 批次灌連結」。

**待實作前再確認的小決策**：Phase 2 同步用手動重跑或 Apps Script 排程、一卡多文件如何帶類型、
Drive API 走 service account 或個人授權。

## [2026-08-13] equipment-cards | 群組/套餐管理架構優化（續：標籤範圍與畫面呈現定案）

**決策結果（3 點待決事項皆已定案）**：
1. **標籤範圍**：CRM 新發現的「附加功能/選配模組」「車輛用途/載運內容」2 個維度**先都納入**，標籤維度共 11 個：客戶、車款、大小車/輪數、安裝位置、有無子車、業務性質、主機型號、鏡頭方案、套餐狀態、附加功能/選配模組、車輛用途/載運內容

## [2026-08-13] equipment-cards | 群組/套餐管理架構優化（最終定案：標籤方案擱置，範圍收斂為批次替換）
