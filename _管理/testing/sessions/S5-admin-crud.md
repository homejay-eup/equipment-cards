# S5 — 瀏覽器測試：管理員料卡 CRUD

## 前置條件

- **類型**：瀏覽器操控
- **工具**：Claude in Chrome（繼承已登入 session）
- **帳號**：管理員（homejay@eup.com.tw）
- **起始頁面**：https://equipment-cards.vercel.app/
- **測試料卡**：使用測試用資料（料號建議加前綴 `TEST-` 方便事後清理）
- **時間預估**：30–40 分鐘

## 注意

- 測試「刪除」時，使用本次測試自己建的 TEST 料卡，不刪現有真實料卡
- 所有破壞性操作前確認有 ConfirmDialog

---

## 測試案例

### TC-5.1：開啟新增料卡表單

- 步驟：找到新增按鈕（管理員才可見），點擊開啟
- 驗證：
  - [ ] CardFormDialog 正確開啟
  - [ ] 所有欄位初始為空（新增模式）

---

### TC-5.2：必填欄位驗證

- 步驟：留空所有欄位，直接點「儲存」
- 驗證：
  - [ ] 料號（必填）顯示錯誤提示
  - [ ] 品名（必填）顯示錯誤提示
  - [ ] API 不被呼叫（client-side 攔截）

---

### TC-5.3：新增料卡（完整欄位）

- 步驟：填入以下測試資料並儲存：
  - 料號：`TEST-001`
  - 品名：`測試料卡 001`
  - 分類：選任意分類
  - 狀態：在庫
  - 廠商：TestVendor
  - 備註：自動化測試建立
- 驗證：
  - [ ] 儲存成功，Dialog 關閉
  - [ ] 首頁能搜尋到「TEST-001」
  - [ ] 點開 Lightbox 確認所有欄位顯示正確

---

### TC-5.4：料號重複衝突

- 步驟：再次新增料號「TEST-001」
- 驗證：
  - [ ] API 回傳 409，UI 顯示「料號已存在」錯誤（非靜默失敗）

---

### TC-5.5：編輯料卡

- 步驟：
  1. 找到 TEST-001，開啟編輯
  2. 修改品名為「測試料卡 001（已編輯）」
  3. 儲存
- 驗證：
  - [ ] Dialog 關閉
  - [ ] 卡片品名即時更新（無需重整）
  - [ ] Lightbox 中也顯示新品名

---

### TC-5.6：取消編輯不保留修改

- 步驟：
  1. 開啟 TEST-001 編輯
  2. 修改欄位
  3. 點「取消」或關閉 Dialog
- 驗證：
  - [ ] 資料恢復為修改前的值

---

### TC-5.7：照片上傳（暫存機制）

- 步驟：
  1. 開啟 TEST-001 編輯
  2. 上傳一張測試照片
  3. 不點儲存，直接關閉 Dialog
- 驗證：
  - [ ] 照片未真正上傳到 Cloudinary（或有清理機制）
  - [ ] 重新開啟 TEST-001，照片不存在

- 步驟（正常流程）：
  1. 再次開啟 TEST-001 編輯
  2. 上傳照片
  3. 點「儲存」
- 驗證：
  - [ ] Lightbox 可以看到上傳的照片

---

### TC-5.8：刪除料卡

- 步驟：找到刪除 TEST-001 的操作，點擊
- 驗證：
  - [ ] 出現 ConfirmDialog（非原生 confirm()）
  - [ ] ConfirmDialog 的文字清楚描述要刪除的料卡
  - [ ] 點確認後 → 料卡從列表消失
  - [ ] 點取消後 → 料卡仍存在

---

### TC-5.9：ConfirmDialog 的取消行為

- 步驟：觸發任意刪除操作，在 ConfirmDialog 出現後點「取消」
- 驗證：
  - [ ] Dialog 關閉，資料未被刪除

---

### TC-5.10：批次匯入（CSV）基本流程

- 步驟：找到批次匯入入口，上傳格式正確的 CSV
- 驗證：
  - [ ] 有預覽或確認步驟
  - [ ] 成功後首頁能看到匯入的料卡

- 步驟（錯誤格式）：上傳欄位錯誤的 CSV
- 驗證：
  - [ ] 顯示清楚的錯誤訊息，不是崩潰

---
