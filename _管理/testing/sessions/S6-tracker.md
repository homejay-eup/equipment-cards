# S6 — 瀏覽器測試：Tracker 議題看板

## 前置條件

- **類型**：瀏覽器操控
- **工具**：Claude in Chrome（繼承已登入 session）
- **帳號**：管理員（homejay@eup.com.tw）
- **起始頁面**：https://equipment-cards.vercel.app/tracker
- **時間預估**：25–35 分鐘
- **重要前提**：管理員帳號若未設定 `department_id`，議題清單可能為空（已知設計：API 回傳空陣列）

## 若 Tracker 顯示空白

PRE-03 預判：管理員沒有 department_id 時 API 回傳 []。
→ 先確認帳號是否有部門設定（`/admin/roles` 或 `/admin/users`）
→ 若確認是 PRE-03 問題，記錄到 bug-log.md，繼續測試其他 TC

---

## 測試案例

### TC-6.1：Tracker 頁面載入

- 步驟：導航至 `/tracker`
- 驗證：
  - [ ] 頁面正常載入（有欄位顯示：待處理 / 處理中 / 已解決）
  - [ ] 無 console error（若可讀取）
  - [ ] 若議題清單空白，確認是否因 PRE-03（無部門）

---

### TC-6.2：新增議題

- 步驟：找到「新增議題」入口，點擊開啟 NewIssueDialog
- 填入：
  - 標題：`[TEST] 測試議題`
  - 類型：選任意類型
  - 優先度：中
- 驗證：
  - [ ] Dialog 正常開啟
  - [ ] 儲存後議題出現在「待處理」欄位
  - [ ] 議題標題顯示正確

---

### TC-6.3：必填欄位驗證

- 步驟：NewIssueDialog 中留空標題，直接儲存
- 驗證：
  - [ ] 顯示「標題為必填」錯誤提示
  - [ ] 留空類型，直接儲存 → 顯示錯誤提示

---

### TC-6.4：議題詳情開啟

- 步驟：點擊剛建立的 `[TEST]` 議題
- 驗證：
  - [ ] IssueDetailDialog 正確開啟
  - [ ] 顯示議題標題、類型、優先度、建立者
  - [ ] 關閉 Dialog 後回到看板（無異常）

---

### TC-6.5：狀態拖拉（Kanban 換欄）

- 步驟：將 `[TEST]` 議題從「待處理」拖拉到「處理中」
- 驗證：
  - [ ] 議題移動到目標欄位
  - [ ] 重整頁面後狀態持久保存

---

### TC-6.6：編輯議題

- 步驟：開啟 `[TEST]` 議題詳情，找「編輯」入口
- 修改：標題改為 `[TEST] 已編輯`
- 驗證：
  - [ ] 儲存後看板上的標題即時更新

---

### TC-6.7：篩選功能

- 步驟：
  1. 測試「只看我的」篩選（assignee=me）
  2. 測試按優先度篩選
  3. 測試按類型篩選
- 驗證：
  - [ ] 每個篩選條件正確縮小顯示的議題
  - [ ] 清除篩選後恢復全部

---

### TC-6.8：刪除議題

- 步驟：刪除 `[TEST]` 議題
- 驗證：
  - [ ] 出現 ConfirmDialog
  - [ ] 確認後議題從看板消失
  - [ ] 取消後議題仍存在

---

### TC-6.9：管理員無部門時的行為（PRE-03 驗證）

- 步驟：確認目前帳號的 department_id 設定（查 `/admin/roles` 或 Supabase dashboard）
- 驗證：
  - [ ] 若 department_id = null，Tracker 顯示空（記錄為 BUG 或已知設計）
  - [ ] UI 是否有說明「需要部門設定才能使用 Tracker」（如無，為 P3 UX 問題）
