## 測試案例

### TC-3.1：初始載入正確性

- 步驟：導航至首頁，等待載入完成
- 驗證：
  - [ ] 卡片網格是否顯示（數量 > 0）
  - [ ] Header 右上角是否顯示用戶名稱/頭像
  - [ ] 搜尋框、分類下拉、狀態篩選是否可見
  - [ ] URL 是否為乾淨的 `/`（無多餘 query string）

---

### TC-3.2：全文搜尋 — 一般關鍵字

- 步驟：在搜尋框輸入「Sony」
- 驗證：
  - [ ] 卡片數量減少，且所有顯示卡片與「Sony」相關
  - [ ] URL 是否更新含 search 參數
  - [ ] 清除搜尋框後，卡片是否恢復全部顯示

---

### TC-3.3：全文搜尋 — 純數字（料號）

- 步驟：輸入一個已知料號數字（例如「1001」）
- 驗證：
  - [ ] 結果是否正確（精確 includes 而非模糊）
  - [ ] 輸入「0000」（不存在）→ 顯示「找不到」提示而非空白

---

### TC-3.4：分類篩選

- 步驟：打開分類下拉，選擇任意一個分類
- 驗證：
  - [ ] 卡片只顯示該分類的料卡
  - [ ] URL query 更新含 category 參數
  - [ ] 次級標籤列（SubfilterTagBar）是否根據選擇的分類出現

---

### TC-3.5：次級標籤篩選

- 步驟：選分類後，再選一個次級標籤
- 驗證：
  - [ ] 卡片進一步縮小至符合次級標籤的範圍
  - [ ] 切換到另一個分類 → 次級標籤自動清除
  - [ ] 選擇「全部」次級標籤 → 退回只有分類篩選

---

### TC-3.6：狀態篩選

- 步驟：依序切換「全部」、「在庫」、「外借」、「報廢」
- 驗證：
  - [ ] 每個狀態切換後，卡片列表是否正確過濾
  - [ ] 某狀態無結果時，顯示「找不到」提示

---

### TC-3.7：多重條件組合

- 步驟：同時設定搜尋詞 + 分類 + 狀態
- 驗證：
  - [ ] 三個條件是否 AND 邏輯（全部符合才顯示）
  - [ ] 修改其中一個條件，其他條件是否保留

---

### TC-3.8：URL 狀態同步與還原

- 步驟：
  1. 設定搜尋詞 + 分類篩選
  2. 複製當前 URL
  3. 開新分頁貼上 URL
- 驗證：
  - [ ] 新分頁是否自動還原相同的搜尋詞 + 篩選狀態

---

### TC-3.9：清除所有篩選

- 步驟：設定多個篩選後，找「清除」或「重置」功能
- 驗證：
  - [ ] 是否有一鍵清除所有篩選的方式（按鈕 or 清空搜尋框）
  - [ ] 清除後 URL 是否恢復乾淨

---

### TC-3.10：空狀態與邊界

- 步驟：搜尋一個不存在的詞（如「zzzzzz」）
- 驗證：
  - [ ] 顯示「找不到」提示，不是空白頁
  - [ ] 清除搜尋後是否正確恢復

---
